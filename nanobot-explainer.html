先说结论

一句话说清楚 nanobot 在干嘛

nanobot 就像一个全能秘书：你在聊天软件里说一句话，它听懂之后去问 AI 大脑（大语言模型）， 如果需要干活就动手（搜网页、读文件、执行命令），最后把结果原路发回给你。

日常比喻

想象你在公司群里 @了一个超级助理。这个助理有一部手机（聊天渠道）， 有一颗聪明的大脑（大语言模型），还有一双手能操作电脑（工具）。 你说"帮我查下明天天气"，它就去查，查到后在群里回复你。nanobot 就是这个助理的「操作系统」。

核心流程

Agent 是怎么「想事情」的？

这是整个 nanobot 最核心的部分。我们一步一步看：当你发了一条消息，Agent 内部到底发生了什么。

1

📨 收到消息

你在 Telegram 里说了句"帮我查一下杭州明天的天气"。Telegram 渠道接收到这条消息， 包装成一个标准信封 (InboundMessage)，写上：来自哪个渠道、谁发的、发到哪个聊天里、说了什么。 然后丢进消息总线。

2

📋 准备上下文

Agent 从总线取出信封，开始「备课」：
① 从 会话管理器 里找到你之前的聊天记录（对话不会一次就忘了）
② 从 记忆系统 里加载长期记忆（比如"用户喜欢简洁回复"）
③ 从 技能库 加载相关能力说明
④ 拼装成一个完整的「提示词」——这就像你要给一个新同事交代任务时，先把背景、要求、注意事项一股脑说清楚。

3

🧠 问 AI 大脑

Agent 把准备好的上下文发给 LLM（大语言模型）——可以理解为一个超级聪明但没有手的大脑。
同时告诉它："你有这些工具可以用——搜索网页、读文件、执行命令……"
AI 大脑思考后可能说："我需要先搜索一下杭州天气"（这叫做「工具调用」）。

4

🔧 执行工具

Agent 看到 AI 说"搜索杭州天气"，于是去执行 web_search 工具。 工具干完活，返回搜索结果："杭州明天晴，25°C"。 Agent 把这个结果再塞进对话里，又发回给 AI 大脑——这就形成了一个循环。

5

🔄 循环直到完成

AI 大脑拿到搜索结果后，可能觉得已经够了，直接组织一段话回复你。 也可能觉得还不够（比如需要再查个温度曲线），那就再调用工具，Agent 再执行，再喂回……
这个「思考→行动→观察→再思考」的循环，最多转 40 圈（防止死循环）。 直到 AI 大脑返回一段纯文字回答——循环结束。

6

💬 回复你

Agent 拿到最终回答，包装成一个出站信封 (OutboundMessage)， 丢进消息总线。渠道管理器从总线取出来，按上面写的"Telegram"渠道，原路送回到你的聊天窗口。
你看到："杭州明天晴天，最高温 25°C，适合出门遛弯～ ☀️"

核心循环比喻

想象你让秘书帮你策划生日派对。秘书先想了一下（AI 思考），然后说"我要先查一下附近的餐厅"（工具调用）， 查完以后带着结果回来继续想（再次思考），发现还需要"预约一下那家评分最高的"（又一次工具调用）， 最后给你一份完整方案。这个「想→做→看→再想」的循环，就是 Agent 的灵魂。

工具箱

Agent 有哪些工具可以用？

工具就是 Agent 的「双手」。AI 大脑再聪明，没有工具也只能空口说白话。 nanobot 内置了这些工具——

📖

read_file · 读文件

读取电脑上的文件内容。比如你说"看看我的 README"，它就能打开看。

✏️

write_file · 写文件

创建或覆盖文件。比如"帮我写个 Python 脚本保存到桌面"，它就直接写了。

🔧

edit_file · 改文件

精确替换文件里的某段内容，不用全部重写。就像用记事本的"查找替换"。

📂

list_dir · 看目录

列出某个文件夹里有什么文件。相当于你在"文件资源管理器"里打开一个文件夹。

💻

exec · 执行命令

在你电脑的终端里执行命令。比如 python script.py 或 git status。有安全过滤，不会执行危险操作。

🌐

web_search · 搜网页

用 Brave Search 搜索互联网信息。就像你打开浏览器搜索一样。

📄

web_fetch · 抓网页

访问一个具体的 URL，把页面内容抓回来阅读。能过滤掉广告等噪音。

💬

message · 发消息

主动给你发消息（不只是回复）。定时任务完成后就是用这个通知你的。

🐣

spawn · 派子任务

把复杂的子任务交给一个"分身"去做，主 Agent 可以继续做别的事。

⏰

cron · 定时任务

设置闹钟。"每天早上 8 点告诉我天气"——它会创建一个定时任务，到点自动触发。

🔌

MCP 外部工具

通过 MCP 协议接入外部工具服务器。就像给 Agent 装了个 USB 扩展坞，想接什么设备都行。

AI 大脑

模型提供商：你的 AI 大脑从哪来？

nanobot 自己不是 AI，它需要调用外面的 AI 模型来「思考」。你可以选择各家 AI 公司—— 就像选手机套餐，哪家实惠选哪家。

比喻

提供商 (Provider) 就像电信运营商。你的手机（nanobot）需要接入信号（AI 能力）， 可以选移动（OpenAI）、联通（Anthropic）、电信（DeepSeek）……功能差不多，价格和质量各有千秋。 有一种叫 OpenRouter 的特殊运营商，它是「虚拟运营商」——一张卡能用所有网络。

自动匹配是怎么回事？

你在配置文件里写 "model": "deepseek/deepseek-chat"，nanobot 看到名字里有 deepseek， 就自动去找 DeepSeek 的 API Key 来用——这就是注册表自动匹配。 每家提供商在代码里注册了自己的"关键词"，模型名里只要出现关键词就能配对上。 你也可以手动指定 "provider": "deepseek"，那就不用猜了。

记忆系统

它怎么记住你说过的话？

nanobot 有两种记忆，短期和长期。就像人一样——你记得今天中午吃了什么（短期）， 也记得自己最喜欢的菜（长期）。

📝 短期记忆：会话 (Session)

就是聊天记录。每次对话都以 channel:chat_id（比如 telegram:12345）为 key 存一份。 存成 JSONL 格式——每行一条消息，简单粗暴。Agent 每次回答前都会把最近的聊天记录带上， 这样它才知道"我们之前在聊什么"。

🧠 长期记忆：MEMORY.md

聊多了以后（默认 100 轮），Agent 会让 AI 把对话浓缩成要点（比如"用户偏好中文回复""用户在做 Python 项目"）， 写进 MEMORY.md。同时把对话摘要追加到 HISTORY.md—— 这是个时间线日记，方便回溯。下次对话开始时，Agent 读取 MEMORY.md，就像"回忆起来了"。

技能系统

Skills：给 Agent 装插件

技能 (Skill) 就像手机 App。nanobot 自带了一些 App（天气、GitHub、定时任务）， 你也可以自己写新 App 装上去。

怎么装技能？

每个技能就是一个 Markdown 文件（SKILL.md），放在 workspace/skills/技能名/ 文件夹下。 Agent 启动时会扫描这些文件，在需要的时候把对应技能的说明注入到提示词里—— 相当于临时给 AI 大脑"补课"。比如"我现在要用 GitHub，先看看 GitHub 技能的说明书"。

自动化

Cron & Heartbeat：让 Agent 自己动起来

Agent 不只是你问它才答。它还能定时做事（Cron）和定期巡逻（Heartbeat）。

⏰ Cron：定时闹钟

你可以告诉 nanobot"每天早上 8 点帮我查天气"，它会创建一个定时任务（像手机闹钟）。 到点了，闹钟响了，Agent 就自动起来干活，干完通过消息总线把结果发到你的聊天窗口。 支持三种模式：一次性（到时间只响一次）、间隔重复（每隔 N 小时）、cron 表达式（高级日历规则）。

💓 Heartbeat：心跳巡逻

每 30 分钟，Gateway 会"敲一下" Agent，说"起来看看有没有需要做的事"。 Agent 读取 HEARTBEAT.md 文件，里面列着一些例行公事（比如"检查邮箱有没有紧急邮件"）。 如果有任务就做，没有就继续睡——像夜间保安的定时巡逻。

{ // 🧠 第一块：AI 大脑设置 "agents": { "defaults": { "model": "deepseek/deepseek-chat", // 用哪个 AI 模型 "provider": "deepseek", // 用哪家提供商 "maxTokens": 8192, // 回复最大长度 "temperature": 0.1 // 创造力（越低越严谨） } }, // 📱 第二块：聊天渠道设置 "channels": { "telegram": { "enabled": true, "token": "BOT_TOKEN" }, "discord": { "enabled": false } // ...其他渠道 }, // 🔑 第三块：AI 提供商的 API Key "providers": { "deepseek": { "apiKey": "sk-xxx" }, "openrouter": { "apiKey": "" } // ...其他提供商 } }
技术清单

用到了哪些技术？

全部用大白话解释一遍——

🐍 Python 3.11+

编程语言。就像说"这本书是用中文写的"——nanobot 是用 Python 写的。

⚡ asyncio

Python 自带的"同时做好几件事"能力。像一个人一边等水烧开一边切菜——不是两个人，是一个人灵活切换。

🔗 LiteLLM

万能翻译器。不管你用哪家 AI（OpenAI/Claude/DeepSeek），都用同一个接口调用。就像万能充电头。

📐 Pydantic

数据校验员。确保配置文件的格式是对的——少写一个字段？类型不对？它立刻告诉你。

🖥️ Typer

命令行工具框架。让你能在终端里输入 nanobot agent 就启动程序，还自动生成 --help 文档。

🌐 httpx

网络请求库。Agent 要搜索网页、调 API，都靠它发 HTTP 请求——就像浏览器背后的"快递员"。

🔌 MCP (Model Context Protocol)

插件协议。让 Agent 能连接外部工具服务器，就像 USB 接口——只要符合标准，什么设备都能插上用。

📦 Hatchling

打包工具。把代码打成可安装的包——就像把散装零件组装成盒装商品，方便别人一键安装。
